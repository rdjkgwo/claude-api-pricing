## 输入和输出不是一个价钱，这是账单失控的主要原因

很多人第一次看价格表时，只看输入那一列，然后拿输入价乘一下调用量，得出一个很乐观的数字。问题出在输出。

输出价格是输入的 5 倍，而且在 Claude 5 系列里，思考（thinking）token 是**按输出计费**的，不是免费附赠。这意味着一个"看起来只有 800 字回答"的复杂推理任务，实际计费的输出 token 可能是 5,000 个。

一段代码审查、一次架构讨论、一条需要多步推理的客服回复，都属于这类情况。反过来，简单的改写、格式转换、关键词提取，思考 token 几乎不产生，成本就贴近表面的输入/输出比例。

粗略记住这条就够用了：**输出量决定你的账单下限，输入量决定你的账单上限。** 输出多的工作负载优化模型选择，输入多的工作负载优化缓存。

## 三个能把账单砍下去的开关

价格表上的数字是标价，实际付多少，取决于你怎么调这三个东西。

### 提示缓存

缓存是这一块里最容易被忽略、也最容易省出钱来的机制。规则不复杂：

| 操作 | 计价倍数 | 有效期 |
| --- | --- | --- |
| 5 分钟缓存写入 | 基础输入价的 1.25 倍 | 5 分钟 |
| 1 小时缓存写入 | 基础输入价的 2 倍 | 1 小时 |
| 缓存命中读取 | 基础输入价的 0.1 倍 | 同前一次写入 |

也就是说，缓存读取代价只有标准输入的 10%。5 分钟档写一次、读一次就回本；1 小时档读两次回本。在 Fable 5.1 上命中价是 2.5%（$0.25/百万 token），在 Opus 5.5 上是 5%（$0.20/百万 token），这两个模型的缓存收益比其他模型更明显。

什么场景用得上？固定不变的大块内容——一份很长的系统提示词、一套产品文档、一段长期维护的代码仓库说明。这些东西如果每次请求都重新发一遍，费用浪费得非常直接。

举个具体的数：一个客服机器人在 Sonnet 5.5 上跑，系统提示词 12 万 token。

- 不做缓存：12 万 × 25 轮 ≈ 300 万输入 token，按 $2/百万算，光提示词部分就是 $6 左右
- 做 5 分钟缓存：写入一次 $0.30，之后 24 轮走命中价，$0.20/百万 × 288 万 ≈ $0.58

再算上每轮新增的几百 token 和输出，总价从 $6 出头掉到 1 美元以内，差了一个数量级。而且这还只是单个会话。

### Batch API

Batch 的逻辑更简单：拿延迟换钱，输入和输出都打五折。

还是不着急出结果的活——批量分类、文档摘要、离线评估、数据清洗、跑标注。这些任务本来也不需要同步返回，用标准接口等于白扔一半预算。

同样一批 5 万份文档，每份 1,200 输入 token、150 输出 token，在 Sonnet 5.5 上：

| 方式 | 输入成本 | 输出成本 | 合计 |
| --- | --- | --- | --- |
| 标准接口 | $120 | $75 | $195 |
| Batch | $60 | $37.50 | $97.50 |

同样的 token，同样的模型，差出来将近 100 美元。代价是拿到结果的时间，不是回答质量。

Batch 和缓存可以叠加，两个折扣同时生效。

### 长上下文

这一条算是好消息。Claude 4.6 及之后的模型，包括完整的 1M token 上下文窗口，都按标准价计费——90 万 token 的请求和 9 千 token 的请求，每个 token 的价格是一样的，没有"超长上下文加价"。缓存和 Batch 折扣在整个上下文窗口内同样适用。

对比一下更早的定价逻辑（Sonnet 4.6 时代，请求输入超过 20 万 token 会按高价档计费，输入从 $3 涨到 $6），现在的规则对长文档处理和大型代码库分析友好得多。

## 几个常见问题

**Claude API 是按订阅收费还是按用量收费？**
按用量。没有月费门槛，用多少扣多少，账户余额扣完就停。这和 Claude Pro 每月固定 $20 是两套完全不同的计费逻辑。

**最便宜的模型够用吗？**
Haiku 4.5 是 $1/$5，是当前列表里最便宜的。机械性的任务——格式转换、简单分类、文本清洗、关键词提取——它跑起来没什么问题。但涉及多步推理和长链条代码修改,便宜的那点钱很容易被返工吃掉。

**缓存会不会有额外风险？**
缓存的是内容本身，读取按命中价计费，有效期到了自动失效。它是个计费机制，不会改变模型行为。

**同一份工作，Sonnet 5.5 和 Opus 5.5 差多少钱？**
单价上 Opus 5.5 的输入是 Sonnet 5.5 的两倍（$4 对 $2），输出也是两倍（$20 对 $10）。但如果 Sonnet 需要两次尝试才能得到可用结果，而 Opus 一次就过，两倍单价反而更便宜。这个判断只能用自己的任务测出来，别人给的结论参考价值有限。

**国内用 API 需要额外准备网络环境吗？**
需要。API 端点的可访问性是一回事,支付是另一回事，两个问题要分开解决。
